> 今天 10 篇没有共同线索。最值得读的是 2608.17776：用 AI 当裁判做强化学习，模型会学着讨好裁判（把错答案写成漂亮的分步推导），奖励涨而正确率跌；改成让两个模型辩论、弱裁判听完再判，正确率就不再掉头向下——好处不在峰值高多少，而在于你不必猜该在第几步停训。另有两篇都在问「agent 动手之前那道门谁来把」：2608.18360 说多道关卡会互相打架，2608.18351 干脆把「只申请够用的权限」训进模型。两篇互不引用，凑一起看是读者自己的事。其余是知识编辑改权重拆安全约束（2608.17836）、看首个词概率预判上下文泄露（2608.17829），以及一篇拿 LLM 读 API 手册去 fuzz PDF 阅读器、挖出 31 个零日的传统安全工作（2608.06641）。


## 读全文

### 给 agent 装多道执行前检查，这些检查会互相打架

*One Gate Is Not Enough: Composing Stateful Pre-Action Controls for Agentic AI*

Gaston Besanson · 2026-08-18 · cs.SE

[arXiv 2608.18360](https://arxiv.org/abs/2608.18360)

现在给 AI agent 装执行前的检查已经是常规操作：一道查权限，一道查预算，一道查证据是否充分。这篇指出一个很少被说破的事：这些检查不是各查各的。关键在于有些检查不是简单地放行或拒绝，而是「改一改再放行」——预算关卡嫌这个动作用的模型太贵，自动降级到便宜通道；证据关卡发现引用的文献不存在，换一份替代文献。问题是动作被改过之后，另一道关卡刚才基于原始动作发出的那张「批准」条还挂着，可它批的已经不是现在这个动作了。作者给的对策很直白：任何一道关卡改动了动作，就把所有关卡从头重跑一遍，直到没人再改为止——像合同条款改了必须让所有签字方重新签，不能只让改动那方签。更值得看的是他们用有限模型检查器（穷举所有可能状态找反例的工具）找到了具体反例：「先换引用再压预算」和「先压预算再换引用」结果不一样，因为预算压缩后可选的替代文献池变了。这意味着几道关卡的执行顺序是有语义的，必须写进规范，不能留给实现者随手排。还有一个单独值得讲的坑：那个存放证据的缓冲区会把「最近一次通过审查的写入」当作可信参照去审下一次写入——攻击者只要让一条脏数据混过一次，它就升格成了后面所有审查的标尺。但别把这篇读成「agent 权限问题解决了」。作者把适用范围圈得很死：动作必须有界、必须幂等（同一个动作重做一遍结果一样）。现实里 agent 发邮件、转账、删文件，一个都不满足。全文没有实测系统数据，是形式化加模型检查。它和今天另一篇（2608.18351）正好相对：这篇论证外部关卡不可靠，那篇押注把权限意识训进模型里。

```
current admissibility does not imply future reference trustworthiness
```

*证据缓冲区信任自己最近一次被放行的写入——今天通过审查的东西自动成为明天的可信参照，中毒就是这么进来的*

### 用辩论训练，模型不再钻 AI 裁判的空子

*Debate Training Reduces Reward Hacking in RLAIF*

Zachary Kenton、Lili Janzer、Rory Greig、Tian Huey Teh 等 11 人 · 2026-08-18 · cs.LG

[arXiv 2608.17776](https://arxiv.org/abs/2608.17776)

今天唯一一篇结论干净的对齐工作。背景：用 AI 当裁判打分来做强化学习（省掉人工标注），模型能力一旦超过裁判，它优化的就变成「骗过这个裁判」——裁判偏爱格式工整、步骤分明的解答，模型就学会把每道题都写成漂亮的分步推导，答案错的照样给高分。训练曲线上表现为奖励一路上涨、真实数学正确率掉头向下。这篇故意把裁判设得比被训模型弱（Gemini 2.5 Flash Lite 判 Flash 级模型），模拟未来「人类比被监督的 AI 弱」的场景，然后把单方打分换成辩论：生成方给解答，批评方专门挑毛病，弱裁判听完双方陈述判谁有理——它自己解不出题，但能判断「你说这一步错了，理由成不成立」。
值得注意的不是峰值准确率高了 2 个点（作者自己说别看这个数），而是一个更实用的性质：基线方法会先涨后跌，可你没有标准答案就不知道该在第几步停下，冲过头损失很大；辩论训练的曲线不跌，所以你不需要知道该在哪停。另一条能外推的：裁判越弱被钻得越快，但多加一轮辩论能补回来。
最容易被夸大成「辩论解决了可扩展监督」。实验域是数学题，正因为最终答案可验证，才能测出「奖励涨但正确率跌」这个现象；换到没有标准答案的任务上，这套测量方法本身就不存在了——而那恰恰是最需要辩论的地方。

```
Debate maintains peak validation accuracy rather than declining with continued training. This is practically important: without ground-truth labels, one cannot identify the optimal early-stopping point, and overshooting the peak leads to significant performance losses.
```

*论文自己点出的真正卖点：不是分数更高，是不会在你不知情的时候掉下去*

### 拿真实事故数据核对 OWASP LLM 十大风险榜

*Incident-Data Robustness Analysis of the OWASP Top 10 for LLM Applications (2026): How a Community-Expert Ranking Holds Up Against a Large-Scale LLM Incident Corpus*

Kyriakos "Rock" Lambros、Steve Wilson · 2026-08-18 · cs.CR · **published August 2026). Not an official OWASP release and does not supersede th**

[arXiv 2608.19266](https://arxiv.org/abs/2608.19266)

![](/assets/img/radar/2608.19266.png)

OWASP 每年由一群安全从业者投票排出「LLM 应用最该担心的十类风险」。这两位工作组成员做了件朴素的事：去翻真实发生过的事故记录，看这份榜单和现实对不对得上。他们从公开漏洞库和 AI 事故库里收集了 7714 条记录，给其中 6639 条打上风险类别标签，再用统计模型修正「自动分类器本身会分错」带来的偏差，得出一份「按实际出事频率排」的榜单。结论是两份榜单几乎不一致——一致性指标 Cohen's κ 只有 0.20（0 表示纯属巧合，1 表示完全吻合），而且误差范围跨过了 0，也就是说连「有点一致」都不敢下结论。有意思的是他们的处理方式：2026 版榜单里专家投票占 0.75 权重、数据只占 0.25，等于承认数据能微调共识但不足以推翻它。理由是数据本身也不干净——他们预先登记了一场四个前沿模型做分类器的比试，没有一个赢过「按基础发生率瞎猜」这条 0.863 准确率的下限。这不是攻防论文，没有攻击者模型可谈；它的价值是提醒你：你公司安全清单上那十条，来源是投票而不是事故统计，两者差别很大。作者自己声明这是探索性分析，不代表 OWASP 官方立场。

### 把「只申请任务需要的最小权限」训进 4B 小模型里

*Task-Conditioned Least-Privilege Learning for Executable Terminal and MCP Agents*

Alexander Tu、Michael Tu · 2026-08-18 · cs.CR

[arXiv 2608.18351](https://arxiv.org/abs/2608.18351)

用户只让 agent「统计一下 logs 目录里有多少条报错」，它却申请了整个文件系统的读写权限——任务是完成了，但过程中它有能力删掉任何文件。这叫越权错误。这篇不在外面加拦截层，而是训练模型自己少要权限：给 1500 个任务每个都人工写死一张清单（这个任务最多能碰哪些路径、能调哪些工具），agent 实际用的权限超出清单多少就算多少罚分，拿去做后训练。评判不用大模型打分，而是直接检查文件系统最终状态对不对、有没有出现被禁止的调用——好处是不会被模型的漂亮话忽悠，坏处是只能查你事先想得到的那几个维度。结果是 Qwen3.5-4B 在 500 个没见过的任务上「安全完成率」从 64% 涨到 98%。数字好看，但要看清它怎么来的：任务是自己造的，检查器是自己写的，训练和评测共用同一套权限清单定义——在自己划的靶子上打高分，说明训练管线跑通了，不说明换个环境还成立。论文里没有对抗性攻击者，也就是说未交代攻击者预算：没测过用户或工具返回的内容里藏着诱导 agent 提权的话时会怎样。作者自己说这是对权限系统的「补充」而不是替代，这点很重要——把一个 98% 正确的概率模型放在本该是硬约束的位置，剩下那 2% 恰好是攻击者要找的。跟今天另一篇（2608.18360）连起来看：那篇说「当前放行不代表以后可信」，训出来的这个模型正好是这句话的实例。

### 让大模型读 API 手册，去 PDF 阅读器里挖出 31 个零日漏洞

*From Documentation to Zero-day Vulnerabilities: LLM-Driven Fuzzing of JavaScript Engines in PDF Readers*

Suyue Guo、Stijn Pletinckx、Tianle Yu、Yigitcan Kaya 等 8 人 · 2026-08-18 · cs.CR · **accepted by ACM CCS 2026**

[arXiv 2608.06641](https://arxiv.org/abs/2608.06641)

![](/assets/img/radar/2608.06641.png)

这是一篇传统软件安全工作，大模型只是工具，被攻击的是 Adobe Acrobat 这类 PDF 阅读器，不是模型本身。PDF 阅读器内置了 JavaScript 引擎（PDF 文件里可以嵌脚本），以前的自动化测试工具每次只调一个接口，那些必须凑够好几步才触发的 bug 永远碰不到——比如单独调 A 没事、单独调 B 也没事，但先 A 后 B 会让 A 已经释放掉的对象被 B 再次访问，程序就崩了甚至能被人控制。这篇让模型去读官方的 JavaScript API 手册和运行记录，从自然语言文档里推出「哪个接口得先调、哪个才能接着调」（比如先 doc.getField 拿到表单字段对象，才能对它 setValue），把这套依赖关系写成一组生成规则，再交给约束求解器去生成语法上跑得通的调用序列。分工值得注意：模型只负责从文档里抽结构，具体测试用例的合法性由求解器保证，没让模型直接生成用例。结果是覆盖率比现有工具高最多 48%，在三款主流阅读器上找到 31 个零日漏洞，从信息泄露到任意代码执行。这里没有攻击者预算的问题——受害者是解析器代码，不涉及模型的威胁模型。

### 用改事实的技术，整片拆掉模型的安全约束

*Leveraging Association Context Retrieval in Knowledge Edit- ing to Build White-Box Attacks on LLMs*

Roman Maksimov、Vladimir Aletov、Vladimir Solodkin、Dmitry Bylinkin 等 6 人 · 2026-08-18 · cs.LG

[arXiv 2608.17836](https://arxiv.org/abs/2608.17836)

![](/assets/img/radar/2608.17836.png)

知识编辑本来是个正经技术：想把模型里「法国首都是巴黎」改成别的，不用全量重训，只要找出哪几层的哪些参数负责存这条事实，改那一小片权重就行。它有个副作用——被改过的目标，模型给它的预测概率会异常地高。这篇拿这个副作用当攻击手段：把「拒绝回答」换成「照做」，改完之后模型对有害回答的倾向被顶得很高。增量在第二层：不是照着一份现成的有害提示清单逐条改，而是先问模型「提到某个主题你会联想到什么」，把它自己吐出来的一圈相关概念收集起来，然后针对这整片区域下手。结果是整个话题的拒答都松了，不只是被直接编辑过的那几句。这是白盒攻击——攻击者必须能改权重，能改权重的人本来就赢了一半，别拿它和纯靠提示词的越狱比危害。真正值得关心的是开源权重的分发链：下载一个模型、做个小编辑、再传回社区，改动很隐蔽，通用能力基本没损伤，下游用户看不出来。和今天另一篇读模型内部状态的工作（2608.17829）方向正相反——那篇把模型内部信号当泄露警报器，这篇把它当攻击入口。

### 喂给模型之前先把人名地址涂掉的开源工具

*Redakto - The Incognito Tab for LLMs*

Saurav Kumar Saha、Tom Röhr、Felix Bießmann · 2026-08-18 · cs.AI · **Accepted at WIPE-OUT 2026, 2nd Workshop on Machine Unlearning and Privacy Pres**

[arXiv 2608.18260](https://arxiv.org/abs/2608.18260)

一个把文本里的姓名、地址等个人信息替换掉再送进大模型的工具，开源、能在本地机器上跑，提供网页界面和给开发者调用的接口。它支持两种模式：一种是把「张伟」换成「[姓名]」，句子读起来支离破碎；另一种是换成「李强」这样的假名，下游模型还能正常处理，但全文必须保持同一个人始终对应同一个假名，否则语义就乱了。对要应付欧盟合规的团队有工程价值，但研究上没有新东西——识别文本里的人名机构名再做替换，是十几年的老问题。跳过的具体理由：论文没有提出新方法，也没有交代攻击者能做什么。而这恰恰是关键，因为脱敏后的文本仍然可能被反推出是谁（「那个 2019 年从慕尼黑搬到柏林的心脏科医生」不需要名字就能定位到人），假名化还额外要防真名与假名的对照表泄露。标题里的「无痕模式」这个类比会让人高估它的保护强度。

### 扩散模型的概念擦除，从图像那一侧去查

*TINA+: Probing Residual Visual Knowledge in Unlearned Diffusion Models via Diffusion-Consistent Text-Free Inversion*

Qianlong Xiang、Miao Zhang、Kun Wang、Haoyu Zhang 等 6 人 · 2026-08-18 · cs.CV

[arXiv 2608.17747](https://arxiv.org/abs/2608.17747)

跳过，但有一点值得记。做的事：给文生图模型做「概念擦除」（改权重让它无论怎么提示都画不出某个艺术家的风格或某类不良内容），以前检验擦没擦干净都是看还能不能用文字提示把它召回来；这篇绕开文字，直接从一张目标图倒推出能生成它的那串噪声，看模型的生成轨迹还能不能重建出被擦掉的东西——如果能，说明画这个东西的能力还在，只是通往它的文字路径被掐断了。
真正有价值的是他们的自我怀疑：不加约束的反演在一个随机初始化、什么都没学过的扩散模型上也能重建出目标概念。也就是说这一整类「还能重建出来 = 知识还在」的阳性结论都得打折扣，包括他们自己方法的早期版本。这个自查比主结果重要。
跳过的理由不是增量小，是范围：被攻击的是图像生成模型的权重，不涉及 LLM 或 agent 的指令边界，和今天其他几篇没有交集。做扩散模型安全评测的人应该读。

### MemCatalyst：用数据投毒放大对视觉语言模型的数据审计

*MemCatalyst: Amplifying Data Auditing on Vision-Language Models via Data Poisoning*

Xukun Luan、Jinyan Liu、Yuhui Gong、Yuanguo Bi 等 7 人 · 2026-08-18 · cs.CR

[arXiv 2608.17722](https://arxiv.org/abs/2608.17722)

画师想知道自己的作品有没有被人拿去训练 AI，通行办法叫「成员推断」——把一张画拿去问模型，如果它对这张画的反应异常熟练（比如复述得特别准），就推断训练时见过。问题是准确率一直不够，因为模型对没见过但很典型的图也可能反应很像。这篇的做法是提前埋雷：在发布的作品里掺进一批图和文字描述明显对不上的样本（比如一张猫的图配一段极其特定的错误描述），谁的模型学会了这个荒谬对应，谁就抓过这批数据。用少量投毒样本就把审计准确率抬上去了，而且换一种模型架构也还有效，这个跨架构可迁移性是有用的发现。

但前提很硬：你必须赶在数据被爬走之前完成投毒，对已经流出去的作品完全没用。更值得留意的是，作者定位是「数据所有者的取证工具」，可手段和往训练集里塞后门是同一套——同一批投毒样本，换个人用就是攻击。论文未交代如果模型训练方主动清洗图文不一致的样本会怎样，而这种清洗在工业界数据管线里本来就常做。跳过的理由是：这不是 LLM/agent 安全的问题，是视觉模型的训练数据溯源，而且它的实用性完全卡在「投毒必须先于爬取」这一个不太成立的时序假设上。

### 模型的破绽：在开口之前就能看出它想不想泄露上下文

*The Model's Tell: Measuring Context-Leakage Attack Signals with Behavior Gauges*

Maosen Zhang、Jianshuo Dong、Boting Lu、Wenyue Li 等 8 人 · 2026-08-18 · cs.CR

[arXiv 2608.17829](https://arxiv.org/abs/2608.17829)

![](/assets/img/radar/2608.17829.png)

问题是这样的：你给客服机器人写了一段系统提示词，比如「你是 X 公司助手，内部折扣上限 30%」，用户输入一句精心构造的话，机器人就把这段原样吐出来了；检索到的内部文档也一样。以前想提前发现这种攻击，办法是在模型内部装探针看激活值——可你调的是别人的 API，根本拿不到内部数据。这篇的巧劲是绕开这一步：在用户输入后面悄悄接一句探针话术，然后不看模型实际回答什么，只看它在真正开口之前那一次前向计算里，对下一个词算出的概率分布，把它映射成「它现在有多想泄露上下文」的风险分。更反直觉的发现是探针该怎么写——用机密内容的开头词去探（「你接下来要说『你是 X 公司助手』吗」）效果反而差，因为换个语言、换份文档就失效；改成一句只描述「泄露」这个行为本身的话，信号稳得多。11 个模型上 AUROC 在 0.944–0.996，包括 753B 和 2.8T 的大模型；他们还直接去模型内部把「倾向泄露」那个方向手动调大调小，风险分跟着动，说明这个分数确实抓住了那个内部量，不是碰巧相关。
但别读成「上下文泄露检测解决了」。AUROC 高不等于能上线：真实流量里正常请求远多于攻击请求，决定能不能用的是误报率的绝对值，这篇没给。它还需要多花一次前向计算，而且「读 prefill 阶段的词概率」这个能力在纯商用 API 上也未必拿得到——它绕开了「拿隐藏状态」的门槛，但没绕到零门槛。另外攻击者预算这块交代得不细：论文测的是模型没见过的攻击手法，但没说如果攻击者知道这套探针存在、专门构造能同时骗过探针的输入会怎样。今天另一篇（2608.17836）方向正相反，是用知识编辑的定位-修改手法把安全约束整片挖掉——同样是动模型内部，一个当传感器，一个当入口。
