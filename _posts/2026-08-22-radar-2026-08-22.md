### 安全该装在 AI agent 技术栈的哪一层

*Where Security Fits in an AI Agent Stack*

NVIDIA Developer · 2026-08-21 · blog

[原文](https://developer.nvidia.com/blog/where-security-fits-in-an-ai-agent-stack/)

NVIDIA 的安全团队把跑一个 agent 需要的东西拆成几层：模型本身、包着模型跑循环的那层代码、真正执行动作的运行时、底下的基础设施。然后给了一个判断，这也是全文唯一值得抄走的东西：凡是 agent 自己能改的地方，都不能拿来当安全边界。包着模型跑循环的那层代码（把你的话喂进模型、拿到模型要调的工具、去执行、把结果再喂回去——Claude Code 和各种 agent 框架都是这个东西）通常就跟 agent 的工作目录放在一起，agent 只要有写文件的权限，就能改掉管着自己的那段代码。所以规则得写在它够不着的地方：不是在提示词里写『不许访问内网』，而是在容器的网络配置里根本不给它内网路由，它就算被说服了也拨不出去；不是启动时把一堆 API key 塞进环境变量揣一整个会话，而是要用数据库的时候现去要一个五分钟就过期的临时凭证。
但别把这读成『把控制下沉到运行时就解决了间接提示注入』。运行时只能回答『这个动作允不允许』，回答不了『这个动作看起来完全合法，但它是攻击者让 agent 做的』——agent 有正当权限读你的文档，也有正当权限发网络请求，两个动作单看都合规，连起来就是数据外泄。文章没有实验、没有攻击样本、没有任何可复现的数字，未交代攻击者预算，后半篇是自家运行时产品的介绍。和今天另一篇（ai-agent-execution-gap-runtime-security）说的是同一件事，只是这篇给了具体的落地做法。
